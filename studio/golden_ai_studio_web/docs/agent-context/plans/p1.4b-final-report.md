## UNIFIED TURN_START CLOCK

All metrics measured from `TURN_START` (moment user text is ready):

```
TURN_START
  ↓
provider_first_token_from_turn_ms (LLM first token)
  ↓
first_text_chunk_from_turn_ms (sentence ready for TTS)
  ↓
tts_request_start_from_turn_ms (TTS synthesis starts)
  ↓
first_audio_bytes_from_turn_ms (first audio bytes available)
  ↓
playback_start_from_turn_ms (KPI - audio starts playing)
  ↓
response_complete_from_turn_ms (full response complete)
```

## EDGE TTS TRUE STREAMING

**YES** — Edge TTS 7.2.8 supports true audio streaming via `Communicate.stream()`.

- Yields MP3 frames as they're generated
- No need to wait for complete sentences
- Audio bytes available immediately
- Can play incomplete MP3 files

---

## AUDIO BUFFER METHOD

- **Sentence Stream:** Complete sentence → MP3 file → WPF MediaPlayer
- **True Stream:** Streaming bytes → temp file → WPF MediaPlayer
- **Buffer:** Bounded (MAX_BUFFER_CHUNKS=10, MAX_BUFFER_BYTES=256KB)
- **Backpressure:** Yes (waits when buffer full)
- **Ordering:** Sequential (chunks played in index order)

## WINNER

**SENTENCE STREAMING** — KPI P50 = 2384ms (-40% vs Legacy)

True streaming is slightly slower (2527ms) due to overhead of writing temp files for each chunk.

Sentence streaming is optimal because:
1. Complete sentences = natural audio boundaries
2. Single temp file per sentence = less I/O
3. Still 40% faster than legacy
