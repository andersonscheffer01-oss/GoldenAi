## Critical Design Rules

### Rule 1: Neutral Recording
Recording MUST NOT use RMS, Silero, or Hybrid to decide when to stop.
- Use fixed time window per scenario (generous, includes trailing silence)
- OR manual stop (user presses Enter to end)
- Always include ~1-2s silence after the phrase
- Same raw buffer delivered to all pipelines A, B, H
- This ensures fair A/B/H comparison

### Rule 2: Correct Metrics
`end_speech_delay_ms` = `endpoint_detected_ms - actual_speech_end_ms`

Since actual_speech_end_ms has no reliable automatic ground truth:
- Record `endpoint_ms` (when each pipeline declares endpoint)
- Record `speech_start_ms` (when each pipeline declares speech start)
- **Do NOT** call utterance duration "end_speech_delay"
- Use transcript/cut-final-word as primary quality metric
- Report endpoint_ms and speech_start_ms separately

## Flow

```
1. User selects scenario (1-8)
2. Recording window announced (e.g., "Gravando por 5s... 3... 2... 1... FALE")
3. Record from mic → numpy int16 array (in memory) with fixed window
4. Run Pipeline A on captured audio (RMS detection)
5. Run Pipeline B on captured audio (Silero detection)
6. Run Pipeline H on captured audio (Hybrid detection, hangover=250ms)
7. STT each pipeline's full captured audio
8. Print comparison table
9. Audio NOT saved to disk
```

## Pipelines

### Pipeline A: RMS
Replay captured audio through RMS detection (same logic as voice.py).
Reports: speech_start_ms, endpoint_ms, utterance_ms.

### Pipeline B: Silero
Feed captured audio frame-by-frame (480 samples/30ms) to SileroVADAdapter.
Reports: speech_start_ms, endpoint_ms, utterance_ms.

### Pipeline H: Hybrid
Feed captured audio frame-by-frame to SileroVADAdapter + HybridEndpoint (hangover=250ms).
Reports: speech_start_ms, endpoint_ms, utterance_ms, hangover_count.
