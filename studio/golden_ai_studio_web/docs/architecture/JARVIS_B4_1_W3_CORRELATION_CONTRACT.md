# JARVIS B4.1 W3 - Correlation Contract

Status: IMPLEMENTED / OPTIONAL IDENTIFIERS PRESERVED

## Identifier meanings

| Identifier | Meaning | Wave 3 source/propagation |
| --- | --- | --- |
| `request_id` | inbound command/request identity | JarvisService command context or compatibility request key |
| `correlation_id` | cross-boundary chain identity | inherited from request context; safe-read facade derives a bounded compatibility chain |
| `session_id` | interaction/session identity | existing task/session boundary when available |
| `conversation_id` | chat conversation identity | carried when the caller already has one |
| `task_id` | task/execution owner | JarvisService, ExecutionService, or TaskManager task |
| `mission_id` | Computer Use mission | carried only by callers that already provide it |
| `run_id` | background/execution run | carried by TaskManager callers when available |
| `approval_id` | one approval lifecycle | generated by SecurityManager and reused on create/consume/failure events |

Absent identifiers remain empty/null in the envelope. Wave 3 does not invent a
second global identity scheme or mutate existing request/task databases.

## Approval chain

The expected relationship is:

```text
request/task
  -> SECURITY_DECISION: APPROVAL_REQUIRED
  -> APPROVAL_CREATED: approval_id
  -> APPROVAL_CONSUMED / mismatch / expired / stale / invalid
  -> TOOL_RESULT or denial receipt
```

The approval token remains single-use and bound to its original tool,
arguments, and command. Action and target mismatch events do not consume a
still-valid token; tampered, expired, and consumed tokens fail closed.

## Sanitization and storage

Every envelope is sanitized recursively before persistence. Secrets in nested
arguments, result, error, metadata, and payload-like fields are redacted. The
envelope is placed in the existing bounded `result` column, so the W3 contract
requires no schema migration and preserves older readers.

## Authority boundary

`jarvis_core.audit.AuditLog` is authoritative for migrated Jarvis events.
`core.audit.AuditLogger`, market JSONL, trading journal, setup history, and
backtest evidence remain separate telemetry/history surfaces. Their existence
does not create a second authority for this migrated scope.
